# perf/bigbrush-p99 (0.10.8): large-brush frame spikes. NUMBERS PROVISIONAL (machine never got to load < 2)
What: profiling showed --benchmark ran strokes in the frame loop (predictive is off); a 240 px dab at 33M moves 3-11M verts = 70-220 ms dab + 40-110 ms upload per frame, all already threaded. Fix: from 2M vertices dabs go to the solver thread (no preview; same dabs, same order), frame-sized batches, frame waits <=12.5 ms then keeps drawing; pen lift no longer blocks. SF_BACKGROUND_DABS=0/1. Also: SF_STROKE_LOG/SF_SYNC_LOG breakdowns, SF_BENCH_MESH_OUT dump, isolated runs delete their /tmp folder on success (benchmarks left 1.3 GB autosaves; /tmp filled).
p99 / stall ms, before (bench-baseline.txt, quiet) -> after (bench-after-load3.txt, load ~3): 15M Clay large 77/136 -> 31/34, 240 px 139/172 -> 31/36; 33M Clay large 139/154 -> 31/40, 240 px 306/325 -> 33/41, Smooth 75/81 -> 31/34; worst stall 325 -> 121 (orbit); release 162 -> 0 ms. p50 within ~2 ms (11-14 ms; 33M 240 px 12.0 -> 14.3). Every 15M/33M stroke p99 < 35 ms.
Final code at load 7.7 (bench-after.txt): strokes p99 26-31 (15M), 29-54 (33M); 33M Move 5.8 s stall + clay-small 226 ms = load (Move doesn't use this path). Re-run `build/sculptforge --benchmark standard` quiet before publishing.
Trade-off: 33M 240 px surface trails more (p50 31 -> 69-108 px) since each dab still costs 100-200 ms; dab counts match (101 vs 99).
Quality: same dabs through both paths are bit-identical (ui_stroke_background; --measure-stroke 3,120/3,240 SF_MEASURE_VERIFY=1). Benchmark scene meshes aren't reproducible run to run on either path (two old-path runs differ 0.26), so cross-run 1e-5 isn't measurable there.
