Troubleshooting: tablets, display, crashes and FAQ

This chapter collects fixes for common problems: start-up and graphics errors, tablets, AI service messages, ComfyUI errors, the camera notch, first-launch warnings on macOS and Windows, where SculptForge keeps its settings, how to reset the interface, and how to report a bug.

SculptForge doesn't start#

SculptForge draws with OpenGL 3.3 (core profile). Almost every GPU from the last decade supports it, but an old driver, a remote desktop session or a virtual machine without 3D acceleration may not.

  1. Update your graphics driver from the GPU maker (NVIDIA, AMD, Intel) or your Linux distribution.
  2. Virtual machines: turn on 3D acceleration in the VM settings.
  3. Remote desktop: some remote sessions only offer an older OpenGL. Run SculptForge locally, or use a remote tool that forwards the GPU.
  4. Linux: on a machine without a working GPU driver, Mesa's software renderer works (slowly): LIBGL_ALWAYS_SOFTWARE=1 sculptforge.

To see why it stopped, start it from a terminal and read the messages. It prints the OpenGL version and GPU it found at start-up (for example OpenGL 4.6 (Core Profile) Mesa 26.1.8 on ...), or the error, such as OpenGL 3.3 context creation failed or Missing OpenGL function: ....

  • Linux: run sculptforge in a terminal.
  • macOS: run /Applications/SculptForge.app/Contents/MacOS/SculptForge in Terminal.
  • Windows: the release build has no console window; if it closes straight away, update the driver first, then read the log file, which holds the same messages.

First launch warnings on macOS and Windows#

The release builds aren't code-signed yet, so the operating system warns the first time.

  • macOS (Gatekeeper): "SculptForge can't be opened because it is from an unidentified developer". In Finder, right-click (or Ctrl+click) SculptForge in Applications and choose Open, then Open again. macOS remembers the choice. On recent macOS versions you may instead need System Settings

Privacy & Security > Open Anyway.

  • Windows (SmartScreen): "Windows protected your PC". Click More info, then Run anyway.

Download SculptForge only from the official releases page on GitHub (the website that Help > Website & documentation opens links to it).

The viewport is slow#

  • Check the triangle count in the bar along the top of the window (Tris). Millions of triangles on a laptop GPU are heavy; Tool > Geometry > Decimate or a lower Voxel Remesh resolution brings it down. See Subdivide, Remesh, Decimate and LODs.
  • Turn off Wireframe (Shift+F) on dense meshes.
  • Hide Parts you aren't working on, or Solo the active one.
  • A large Gaussian splat capture costs GPU time too: lower the count with Clean floaters, or untick Show in Render > Gaussian Splats while you sculpt.
  • On laptops with two GPUs, make sure SculptForge runs on the dedicated one (in the GPU maker's control panel or the operating system's graphics settings).
  • Edit > Preferences > Performance: lower Antialiasing (or turn it off), keep Fast Navigation on, and look at Last stroke to see whether brushes or the graphics card take the time. Step down a subdivision level for big changes. See Performance and big meshes.
  • A Part missing from the view with "Not enough GPU memory" in the status bar didn't fit on the graphics card: hide other Parts or step down a level.

Pen tablets#

SculptForge reads pen pressure through the operating system's standard pen input, so most Wacom, XP-Pen, Huion and similar tablets, and pen displays, work without settings.

  1. Open Sculpt > Draw & Tablet. Under Tablet it shows "Pen pressure: 0.42" once the pen has come near the tablet, or "No pen detected".
  2. Pressure > strength (on by default) and Pressure > size choose what pressure controls. They are also on the top shelf.
  3. A custom brush can also set its own pressure response (pressureCurve in its recipe, see Brush Lab and sharing brushes).

Edit > Preferences > Input and Edit > Preferences > Tablet show "Pressure: on" once the pen has pressed, or "Pressure: not detected". Without pressure the pen still draws, at full strength. A tablet plugged in while SculptForge runs works straight away; the status bar says "Tablet connected" (also through Wacom Bridge).

If no pen is detected or pressure doesn't change:

  • Install or update the tablet maker's driver.
  • Windows: SculptForge reads pressure through Windows Ink, and through the driver's Wintab when Windows Ink is off (Wacom Tablet Properties > Mapping > Use Windows Ink). If pressure is still missing, switch that option and bring the pen back to the tablet. See Pen tablets on Windows.
  • Linux: check that the system sees the pen as a tablet (for example in your desktop's tablet settings).
  • If the cursor moves but strokes have no pressure, test in another application to see whether the driver reports pressure at all.
  • The active Part changed by itself: a Part becomes active with Alt+click on it (the keyboard's Alt, a quick click), a triple-click with the mouse or a click in the Parts list; the status bar names it and how. A tablet's ExpressKey set to Alt counts as the keyboard's Alt.
  • The cursor jumps back when you put the pen down elsewhere: the tablet driver is set to mouse (relative) mode. Turn on Edit > Preferences > Tablet > Mouse mode (relative). It also makes the pen relative with the driver in pen mode; the arrow is drawn at the brush while the pen is in range.
  • The pen picks a brush, then stops clicking menus or the canvas until you use the mouse (Huion, display tablets, Wacom; 0.10.8 and earlier): update to 0.10.9 or later. If it still happens, tell us the tablet, its driver version and whether Windows Ink is on.
  • With two screens, the app slows down when the pointer is on the other screen: fixed in 0.10.9; SculptForge now rests only when its window loses focus.

Brush Lab#

The default Free provider uses a hosted open model with no account. If it is unreachable and Ollama runs on your computer, SculptForge uses your local model instead. "Rate limited by the provider" means too many requests in a short time: wait a few seconds. For setup of local models, see Brush Lab and sharing brushes.

No connection at all#

AI features need internet access (except a local Ollama, LM Studio or ComfyUI). Behind a company proxy or firewall, ask IT to allow the service you use: huggingface.co (and *.hf.space), fal.ai, meshy.ai, or the Pollinations.ai text endpoint for the free Brush Lab model.

The interface#

The top of the window is hidden behind the camera notch#

On MacBooks with a camera notch, SculptForge keeps the interface below the notch when it fills the screen. If the title strip or palette bar is still covered, or a plain band appears where you don't want one, change Edit > Preferences > Interface > Camera notch: Automatic (asks the system on macOS, recognises notched MacBook displays on Linux), Always reserve, or Off. F11 switches between fullscreen and a window.

Text and buttons are too small or too large#

Edit > Preferences > Interface > UI scale sets the size (Automatic, 100% to 200%) and applies it at once. Press Store Config (Ctrl+Shift+I) to keep it for the next start. Automatic uses the scale of the monitor the window is on: on Windows that is Settings > Display > Scale, per monitor, and the interface follows when you drag the window to another monitor. On Linux under X11 it comes from the desktop's font DPI (Xft.dpi); if Automatic looks wrong there, pick a size.

My layout or shortcuts are gone after a restart#

Like ZBrush, SculptForge never saves the layout on its own. Press Store Config (Ctrl+Shift+I) to keep the current layout, shortcuts and interface preferences. See The interface.

Reset the interface#

  • Edit > Preferences > Config > Restore Standard UI returns to the built-in layout and default shortcuts. Press Store Config afterwards to make it stick.
  • Restore Custom UI goes back to what the last Store Config saved.
  • To start completely fresh, quit SculptForge and delete ui.json (layout, shortcuts, interface preferences) and imgui.ini (positions of floating windows such as Brush Lab) from the settings folder below.

A key does nothing#

Shortcuts don't fire while you type in a text field: click the canvas first. Check the key in Help > Controls (F1), which shows every shortcut as currently assigned; a key you reassigned shows in orange in Edit > Preferences > Hotkeys, where Default shortcuts undoes every change.

Where settings live#

SculptForge keeps its settings in one folder per user:

SystemSettings folder
Linux~/.local/share/SculptForge/SculptForge/ (or $XDG_DATA_HOME/SculptForge/SculptForge/)
macOS~/Library/Application Support/SculptForge/SculptForge/
Windows%APPDATA%\SculptForge\SculptForge\ (usually C:\Users\<you>\AppData\Roaming\SculptForge\SculptForge\)
File or folderWhat it holds
ui.jsonLayout, shortcut changes and interface preferences, written by Store Config
imgui.iniPositions and sizes of floating windows
ai.jsonAI settings: providers, models, keys, ComfyUI address (readable only by your account)
project.jsonRecent files and the autosave interval
autosave.sfprojThe autosaved copy of unsaved work (removed once you save)
clean_exitMarks a normal exit; without it, the autosave is offered for restore
sculptforge.log, sculptforge-previous.logWhat this session and the last one did, and what crashed (see The log file)
console_history.txtThe console's command history
recent_actions.txtRecently used entries of the command palette
brushes/Your brush library, one .sfbrush file per brush
brush-gallery-cache/, brush-gallery.jsonCommunity brush gallery cache and its address
thumbs/Cached Library and picker thumbnails (safe to delete)

Your library folder (projects, tools, alphas, images, splats and snapshots shown in the Library) is separate: Documents/SculptForge by default, changeable in Edit > Preferences > Library > Library folder.

Tip: To move settings to another computer, copy ui.json, ai.json and the brushes folder. For a shared layout, use Edit > Preferences > Config > Save UI... and Load UI... instead.

The log file#

SculptForge writes what it does to sculptforge.log in its settings folder. Choose Help > Open log folder to open it:

SystemLog file
Windows%APPDATA%\SculptForge\SculptForge\sculptforge.log
macOS~/Library/Application Support/SculptForge/SculptForge/sculptforge.log
Linux~/.local/share/SculptForge/SculptForge/sculptforge.log

It holds the version, your system and GPU (the OpenGL ... on ... line), warnings and errors, and each command you ran. If SculptForge crashes, it ends with lines starting CRASH: that say what crashed and what was done last. Every start keeps the previous session's log as sculptforge-previous.log beside it, so after a crash attach sculptforge-previous.log to your report (the new sculptforge.log is the session after it). It holds no models and no keys, only command names and messages, which may include file names.

Recovering work after a crash#

SculptForge autosaves unsaved work every 5 minutes by default (Edit > Preferences > Autosave, 0 turns it off). After a crash, the next start asks "SculptForge did not close normally last time. Restore the autosaved work?". Restore opens it as unsaved work (save it under a name); Discard deletes it. See Projects, autosave and snapshots. The dialog also points to the crashed session's log file.

Frequently asked questions#

Can SculptForge open ZBrush files (.ZTL, .ZPR)? Not directly: they are proprietary and undocumented. Convert ZTools once in ZBrush with the free SculptForge ZTL Export plug-in, then open the .ZTL in SculptForge (see Coming from ZBrush). Or use Send to ZBrush, or export OBJ or FBX from ZBrush (see Exporting, Send to Unreal and ZBrush). .ZPR projects can't be converted; open their ZTools instead.

Does it have subdivision levels, DynaMesh, ZRemesher or UVs? Voxel remesh works like DynaMesh, Quad Remesh like ZRemesher (with Project All to bring the detail back; see Quad retopology), Auto UV unwraps any model, and Divide adds subdivision levels you can step up and down (see Subdivision levels). Dynamic on the top shelf is dynamic topology, like Sculptris Pro (see Dynamic topology).

Is it really free? Can I sell what I make? Yes and yes. SculptForge is GPL-3.0-or-later free software; the licence covers the program, not your models. The AI models have their own licences (see Image and text to 3D).

Does SculptForge send anything about me anywhere? No. There is no telemetry and no account. AI features talk only to the service you choose, when you use them.

Does it work offline? Yes. Everything except the hosted AI services works offline, and Brush Lab and image-to-3D can run on local models (Ollama, LM Studio, your own ComfyUI or generator command).

Where are my brushes? In the brushes folder in the settings folder above. Brush Lab saves every brush you make or refine there.

Report a problem#

Choose Help > Report a problem to open the issue tracker on GitHub (you need a free GitHub account). A good report includes:

  1. The SculptForge version (Help > About SculptForge) and your operating system.
  2. Your GPU and driver: the OpenGL ... on ... line SculptForge prints at start-up (see SculptForge doesn't start), or the GPU name from your system settings.
  3. Steps to reproduce: what you did, what you expected and what happened instead.
  4. The commands you ran: open the console (the backtick key, left of 1), click Copy session as script and paste it into the report. It often reproduces the problem exactly.
  5. After a crash, the log: sculptforge-previous.log from Help > Open log folder (see The log file).
  6. A file if the problem is with a particular model (a small .sfproj or the original file), and a screenshot for display problems.

For a security problem, don't open a public issue; follow SECURITY.md in the repository instead.
