Scripting and automation

Every operation in SculptForge is a named command with parameters. The same commands run from the console inside the app, from script files, from the sculptforge-cli tool on a build farm, from Python, and from AI agents through the Model Context Protocol (MCP). This chapter explains the script language, the console, both command-line programs, the Python module and connecting AI tools.

The script language#

A script is a list of statements. Each statement is a command name followed by name=value parameters:

new_sphere subdivisions=5
subdivide levels=1
remesh resolution=256; decimate ratio=0.5      # two statements on one line
export_glb path="My Sculpts/bust.glb"

The rules:

  • Statements are separated by new lines or by ;.
  • # starts a comment that runs to the end of the line (outside quotes).
  • Parameters are name=value with no spaces around =.
  • true and false are booleans; numbers are numbers; anything else is text.
  • Put text in double quotes when it contains spaces, ;, # or ", or when it must stay text even though it looks like a number. Inside quotes only \" and \\ are escapes, so Windows paths such as "C:\Users\me\head.obj" work as written.
  • Colours with a # must be quoted: set_color color="#d9a07a".
  • Paths are UTF-8. Relative paths are relative to the current folder of the program running the script.

Scripts stop at the first command that fails.

The console#

Press the backtick key (left of 1), or choose File > Script > Console, to open the console strip above the bottom shelf. Drag its top edge to resize it.

  • Every command you run appears in the console as a script line, whether it came from a button, a shortcut, the command palette or the console itself, followed by its result. Failures show in red with the reason.
  • Type a statement and press Enter to run it. Several statements separated by ; run in order and stop at the first failure.
  • Tab completes command names, then parameter names. Press Tab again to list the candidates.
  • Up and Down walk through the last 200 lines you typed. The history is kept between sessions.
  • help (or ?) lists every command; help remesh explains one command and its parameters.
  • clear empties the log.

The console buttons (also in File > Script):

ButtonWhat it does
Run script file...Runs a text file of statements (.sfscript or .txt), stopping at the first failure
Copy session as scriptPuts every command run this session on the clipboard as a script you can save and run again
Clear consoleEmpties the log. The session script is kept

Tip: To record a macro, work normally, then click Copy session as script, paste it into a text file and edit out what you don't need. Run it later with Run script file... or sculptforge-cli -f.

The command palette#

Press F3 (or Ctrl+Shift+P, or click Search at the top right of the window) to search every command, brush and setting by name. Enter runs the highlighted entry; Shift+Enter opens it in the console so you can add parameters first. Commands that need parameters always open in the console. With an empty search, the palette lists what you used recently. See The interface.

Tip: Hold Ctrl+Alt and point at a button to see the scripting parameters of the command behind it.

sculptforge-cli#

sculptforge-cli runs commands without a window: on a server, a render farm node or in a build pipeline. It keeps one scene for the whole run, loads your brush library (and studio brushes), and uses the same ai.json settings as the app.

sculptforge-cli [options]

  -c, --command "<script>"   Run commands, separated by ';' (can be given several times)
  -f, --file <script.txt>    Run commands from a file ('-' reads standard input)
      --set NAME=VALUE       Define a variable; script values written $NAME are replaced
  -l, --list                 List every command and its parameters
      --schema               Print the commands as LLM tool definitions (JSON)
      --mcp                  Run as an MCP server on standard input and output
  -q, --quiet                Only print errors
  -h, --help                 Show this help

Each command prints its result on one line (export_glb: Exported out/rock.glb). The exit status is 0 when everything succeeded, 1 for a usage or script syntax error, and 2 when a command failed (the error names the line and the command).

Variables make one script reusable. A value written $NAME (the whole value) is replaced with the --set value, so paths with spaces stay intact:

cat > lods.sfscript <<'EOF'
open path=$in
remesh resolution=256
export_lods path=$out levels=4 ratio=0.5
EOF
for f in rocks/*.obj; do
  sculptforge-cli --set in="$f" --set out="lods/$(basename "$f" .obj).glb" -f lods.sfscript
done

More examples:

# Concept art -> sculptable model -> USDZ (free, via Hugging Face)
sculptforge-cli -c 'image_to_3d path=hero.png; export_usd path=hero.usdz'

# Design a brush (free, no key) and save it for the team
sculptforge-cli -c 'brush_ai prompt="weathered stone edges"; brush_save path=stone.sfbrush'

# Cavity dirt on a sculpt, then a coloured PLY
sculptforge-cli -c 'open path=bust.sfproj; paint_from_cavity color="#3a2a20" strength=0.8; export_ply path=bust.ply'

Warning: Without the quotes, #3a2a20 would start a comment. In a shell, put the whole script in single quotes so the double quotes reach SculptForge.

Python#

SculptForge has a Python module, sculptforge, with the same commands plus NumPy access to the mesh. It is included in the VFX Reference Platform builds and the Rez package (see For studios); when building from source, configure CMake with -DSCULPTFORGE_BUILD_PYTHON=ON.

import sculptforge as sf

doc = sf.Document()                                  # loads your brush library, like the app
sf.run(doc, "open", path="/show/troll/troll_base.fbx")
sf.run(doc, "remesh", resolution=320)
sf.run_script(doc, "decimate ratio=0.25; export_lods path=/out/troll.glb levels=4")

verts, tris = doc.vertices, doc.triangles            # NumPy (N, 3) float32 and (M, 3) uint32
doc.set_mesh(verts * 1.1, tris)                      # bring in a mesh from your own tools (clears undo)

print(doc.parts)                                  # [{'name': ..., 'visible': ..., 'triangles': ...}]
doc.active_part = "Helmet"                        # select by index or name
for name, weight in doc.layers:                      # sculpt layers (blend shapes)
    print(name, weight)

print([c["name"] for c in sf.commands()])            # every command with its parameters
Function or propertyWhat it does
sf.run(doc, command, **params)Runs one command and returns its message
sf.run_script(doc, script)Runs a script in the syntax above and returns the messages
sf.commands()Lists every command with its parameters
sf.tool_schema()The commands as LLM tool definitions (JSON)
doc.vertices, doc.base_vertices, doc.normals, doc.trianglesMesh arrays of the active Part (copies)
doc.mask, doc.colors, doc.facegroups, doc.hiddenAttribute arrays you can read and assign (None if absent)
doc.layers, doc.layer_delta(i)Sculpt layers as (name, weight) and their per-vertex offsets
doc.parts, doc.active_partThe Parts list and the active Part
doc.splat_countNumber of loaded Gaussian splats

Failures raise sculptforge.CommandError. Long operations release the GIL, so you can run them on worker threads.

AI agents (MCP)#

An AI tool (Claude Code, Claude Desktop, Cursor and others) can work in the SculptForge window while you watch. The AI blocks out a starting point and shows you options; you do the art. Help > Connect an AI tool... is the guide in the app, on one screen; it is there while AI features are on (Edit > Preferences > AI). It says what this section says, in the same words.

Connect an AI tool#

1. Pick your tool. The window shows the exact command or settings for your install, with Copy. SculptForge is listed as sculptforge-live and started as sculptforge-cli --mcp --attach, so it sits beside a sculptforge entry you may already have (the headless server, below). Claude Code, in a terminal:

claude mcp add --scope user sculptforge-live -- /path/to/sculptforge-cli --mcp --attach

Claude Desktop: add this to its configuration file (Settings > Developer > Edit Config), then restart Claude Desktop:

{
  "mcpServers": {
    "sculptforge-live": { "command": "/path/to/sculptforge-cli", "args": ["--mcp", "--attach"] }
  }
}

Cursor takes the same entry in ~/.cursor/mcp.json. For every other tool, use its setup from the table in Every other tool with the name sculptforge-live and the arguments --mcp --attach; the window writes it out for you. Where sculptforge-cli is on your system: Where sculptforge-cli is.

2. Let it work in this window. Turn on Let AI tools control this window, right there in the window's step 2 (the same switch as in Edit > Preferences > AI). It is off by default, and gone while AI features are off.

3. What happens next.

  • Ask your AI tool for something (examples below). SculptForge shows Let an AI tool control this window? with a 6-digit code: click Approve, or tell the AI the code. Approval lasts until it disconnects.
  • While it works, the AI connected badge sits at the bottom right. Disconnect stops it (also in the command palette: Disconnect AI tool; turning the switch or AI features off disconnects it too).
  • Every step lands in Undo as AI: ..., so you can step back.
  • It asks you first (Allow this AI step?) before files outside the project, scripts and the network: reading or writing files outside the project folder and the files you picked, overwriting a file, saving over the project, deleting library files, running a macro or script, and anything that uses the network (Generate 3D, AI Brush, the brush gallery). Deny and it is told not to retry. Installing or switching packs and the AI switch itself are never offered.
  • It sees the viewport; what it sees goes to that tool's AI service. viewport_image returns the viewport as you see it, view_turntable the model from 4 to 8 sides in one picture, view_set turns and frames your camera, and stroke_screen draws a brush stroke in screen space. With blockout (a Forge Sphere armature in one call), measure and scene_overview it can look, think and correct.

Try asking:

  • "Block out a creature head with horns for me to sculpt."
  • "Look at my model from all sides and tell me what to fix."
  • "Make three rock variations I can refine."
  • "Teach me: walk me through sculpting an ear, step by step."

The recipes your AI tool lists as prompts (creature head, stylised bust, game-ready, rock variations, teach me) work here too.

How it is kept safe: the connection is a Unix socket (owner-only, in your runtime folder) or, on Windows, a named pipe only your user account can open; there is no network port. Only one AI tool can be connected at a time, requests are rate limited, and what the tool sends is data: tool names and values, never code to run.

Without a window: the headless server#

sculptforge-cli --mcp runs SculptForge as an MCP server with a scene of its own, no window needed: for batch jobs and your own agents. The AI tool gets every command as a tool and works on that scene for the session: it can open files, generate models, sculpt strokes, remesh, paint and export. It starts sculptforge-cli on your computer and talks to it over standard input and output. Nothing listens on the network, and nothing is installed into the AI tool. The setups below use the name sculptforge and --mcp; the Claude Desktop bundle is this server too.

Using it#

Ask for something like "make a sphere, remesh it at 128 and export it to ~/Desktop/ball.glb". File paths are on your machine. The headless server works on its own scene; to see the result, open the exported file in SculptForge (or use live mode, above, to watch it work).

  • viewport_image gives the agent a picture of the scene (a clay-shaded view of the visible Parts, any angle) to check each step by eye. Every tool call is one undo step, so the agent can take back what went wrong.
  • Recipes: the server offers ready-made prompts that walk an agent through a whole job. In Claude Desktop and other tools that show MCP prompts, pick one from the prompt menu: a creature head from a description, a stylised bust from a reference image, a game-ready asset (retopology, UVs, baked maps and LODs for Unreal or Godot), rock variations, and a step-by-step lesson.

Your own agent#

The OpenAI Agents SDK starts the server itself:

import asyncio
from agents import Agent, Runner
from agents.mcp import MCPServerStdio

async def main():
    async with MCPServerStdio(name="SculptForge", client_session_timeout_seconds=60,
                              params={"command": "/path/to/sculptforge-cli", "args": ["--mcp"]}) as sf:
        agent = Agent(name="Sculptor", instructions="Use SculptForge's tools.", mcp_servers=[sf])
        print((await Runner.run(agent, "Make a sphere, remesh it at 128 and export ball.glb")).final_output)

asyncio.run(main())

For plain function calling with any model API, sculptforge-cli --schema prints every tool as JSON (name, description, input_schema: the Claude API takes it as it is). APIs limit how many tools one request may carry, so pick the ones the job needs. This helper turns them into function definitions and runs each call in one SculptForge session (through --mcp, so the scene is kept between calls):

# sf_tools.py
import json, subprocess
CLI = "/path/to/sculptforge-cli"
WANTED = {"new_sphere", "remesh", "subdivide", "stroke", "decimate", "mesh_info", "export_glb", "undo"}
TOOLS = [{"type": "function", "name": t["name"], "description": t["description"], "parameters": t["input_schema"]}
         for t in json.loads(subprocess.run([CLI, "--schema"], capture_output=True, text=True).stdout)
         if t["name"] in WANTED]
_sf = subprocess.Popen([CLI, "--mcp"], stdin=subprocess.PIPE, stdout=subprocess.PIPE, text=True)
def call(name, arguments):
    _sf.stdin.write(json.dumps({"jsonrpc": "2.0", "id": 1, "method": "tools/call",
                                "params": {"name": name, "arguments": arguments}}) + "\n")
    _sf.stdin.flush()
    return json.loads(_sf.stdout.readline())["result"]["content"][0]["text"]

OpenAI API (Responses API). For the xAI API use the same code with OpenAI(api_key=os.environ["XAI_API_KEY"], base_url="https://api.x.ai/v1") and a Grok model:

import json
from openai import OpenAI
from sf_tools import TOOLS, call
client = OpenAI()
items = [{"role": "user", "content": "Make a sphere, remesh it at 128 and export it to ball.glb"}]
while True:
    r = client.responses.create(model="gpt-6-astra", tools=TOOLS, input=items)
    items += r.output
    calls = [i for i in r.output if i.type == "function_call"]
    if not calls: break
    items += [{"type": "function_call_output", "call_id": c.call_id,
               "output": call(c.name, json.loads(c.arguments))} for c in calls]
print(r.output_text)

Gemini API (the google-genai package):

from google import genai
from sf_tools import TOOLS, call
client = genai.Client()
interaction = client.interactions.create(model="gemini-3.8-flash", tools=TOOLS,
                                         input="Make a sphere, remesh it at 128 and export it to ball.glb")
for step in interaction.steps:
    if step.type == "function_call":
        print(step.name, call(step.name, step.arguments))
# Send each result back as Google's guide shows to let the model continue.

Never point a tool at a web app's session or cookies: use each vendor's own app, CLI or API as above.
