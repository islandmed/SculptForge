How fast is the SculptForge development build?

Measured with SculptForge's own benchmark on the same machines, the slowest one first. Every number on this page comes with the steps to repeat it. If your computer gives a different answer, send it to us; we list results that disagree with ours too.

Every figure is the median of three runs of sculptforge --benchmark on the release build of the main branch (the development build, commit 308f83c, after 0.12.10; not yet a released version, no video), one run at a time on a machine with nothing else testing. Each row links to the raw result files exactly as the program wrote them and to its rows in the results table. The scenes are built from a formula, so they are the same on every computer. We removed earlier figures that rested on a scan we cannot redistribute; a figure comes back when it has a public scene and a raw result. The stroke-lag figures are the honest weak spot: a 240 px brush on a dense mesh lands its stroke about a second behind the pen. The entry-level rows are the simulated tier on an Apple M1 Pro laptop: the setting limits what the app may use (memory, detail, OpenGL 3.3), not how fast the laptop is, so some rows read faster than the desktop and real entry-level hardware will be slower. They are listed because they exercise the budgets, not as a prediction for a particular computer.

The machines, slowest first

A speed claim counts only if it holds on the first tier that has a number. Today no real integrated-graphics laptop is in the set; until a tester reports one, the low-end budget is simulated (below) and every result says which tier it is.

Low-end budget, simulated

An Apple M1 Pro laptop running Linux, limited to a low-end machine's budgets and OpenGL 3.3 (SF_HW_SIMULATE=floor), on its fast cores, or on its two efficiency cores for the harshest CPU case.

Laptop

The same Apple M1 Pro laptop (32 GB shared memory), Linux, no limits.

Desktop

What's still slow

  • Big brushes (120 and 240 px) on very dense meshes still trail the pen on every machine we test, the desktop included: the stroke lands, but late (the lag row above).
  • Orbiting 104 million real triangles right after a stroke has one very slow frame on the desktop (the 100M sphere row), although the average is far above 30 frames a second.
  • The figures use scenes made from a formula (smooth, with no sculpted detail beyond the head's shape); a file with sculpted micro detail can behave differently. We publish no figure for a scene we cannot share.
  • No real integrated-graphics laptop is in the measured set yet; that tier is simulated, and a simulated result does not say so in its JSON (the command above does).

Repeat it on your computer

  1. Install

    Any build from the download page (free, no account), or a build of the commit named in the raw file. Close builds, games and renders.

  2. Run the same scenes

    Each run builds its scene from a formula (nothing to download), draws scripted Clay strokes through the real pen code, then orbits, and writes a JSON result.

  3. Compare

    Run each scene three times and take the median. Send your files; we list results that disagree with ours too.

The exact commands 
sculptforge --benchmark standard-33m --benchmark-no-video --benchmark-out head-33m.json
sculptforge --benchmark core-100m    --benchmark-no-video --benchmark-out core-100m.json
sculptforge --benchmark core-200m    --benchmark-no-video --benchmark-out core-200m.json
sculptforge --benchmark --benchmark-sizes 100 --benchmark-no-video --benchmark-out sphere-100m.json

# the simulated low-end budget we report first
SF_HW_SIMULATE=floor SF_GOVERNOR=0 sculptforge --benchmark standard-33m --benchmark-no-video --benchmark-out head-33m-floor.json

On macOS and Windows, run the same arguments with the installed program; on Windows set the variables first in a Command Prompt (set SF_HW_SIMULATE=floor) and run sculptforge.exe from the install folder. The 100 million triangle sphere needs about 16 GB of free memory. The files' fields are described in docs/benchmark.md.

Reading the result

  • Stroke lag (lag_ms): from the pen sample to the frame on screen that shows its dab. p50 is the typical dab, p99 the slow ones you feel.
  • Release (release_done_ms): from pen up to the whole stroke in the mesh and shaded.
  • Slowest frame (worst_stall_ms): the longest frame in the run, including lifting the pen.
  • Orbit: frames per second while the view turns once in 3 seconds after the strokes.
  • Memory: peak RAM plus GPU buffers.

Full method, every tier and the raw numbers: the performance scoreboard. Format of the JSON file: docs/benchmark.md. Send yours: submit a result.

Comparing with other apps

This page lists SculptForge's numbers only. We don't run, publish or test other sculpting applications. The scenes are built from a formula, so you can build a similar mesh elsewhere and judge for yourself.
