33 to 805 million triangles, measured

Can an open-source sculpting app handle high-poly work? Don't take our word for it. These are SculptForge's own numbers on a 15 and a 33 million triangle head and on micro-level scenes up to 805 million triangles, from a benchmark anyone can run with one command, on the same scene with the same strokes. Run it on your computer and compare.

What is listed below (2026-11-12, development build, commit 308f83c, after 0.12.10). Three runs each of --benchmark standard-33m, core-100m, core-200m (micro levels, 104 and 201 million micro triangles) and --benchmark --benchmark-sizes 100 (a subdivided sphere of 104 million triangles), on the release package, one at a time, no video. Every row has a Raw link to the JSON exactly as the program wrote it (the hardware fields are what the program reports; nothing else is added). The simulated low-end rows were run with SF_HW_SIMULATE=floor SF_GOVERNOR=0 on the laptop listed; that setting is not part of the JSON, so those rows say it in their machine line. The headline figures on the How fast? page are the medians of these rows.

The scene pack: compare your computer with everyone else's

A small download of our own sculpts and one command. It measures how SculptForge feels on your computer, writes a file with your hardware and the numbers, and you can add it to the table below. Nothing leaves your computer unless you paste the file into an issue yourself.

Download the scene pack (50 KB) version 1, CC0, source

unzip sculptforge-bench-pack-1.zip
sculptforge --benchmark-pack sculptforge-bench-pack-1 --out results.json

Linux, macOS and Windows, about 5 minutes, needs the latest SculptForge release. Your own settings and files are not touched; no video is made. Close heavy programs first.

  • floor creature-floor, 5.8 million triangles: the entry-level test every supported computer should carry, integrated graphics included.
  • standard creature-standard, 23 million triangles: a mid-range computer.
  • high creature-high, 92 million triangles: a workstation (about 14 GB of free memory; skipped, and said so, when the computer has less).

Each scene gets the same scripted pen strokes (Clay at three sizes, Move, Smooth, a 240 px brush, an orbit) through the code a real pen uses. The file lists your CPU, graphics card and driver, memory and operating system (read by the program, nothing typed), the SculptForge version and, per scene and stroke, frame time p50 / p95 / p99, frames a second and the slowest frame. Stroke timings are being re-measured. The format: docs/benchmark.md.

Or run the standard scenes in 3 steps

  1. Get SculptForge

    Install the latest release (free, Linux, macOS, Windows). Close anything heavy: builds, games, renders.

  2. Run the standard scene

    Help > Benchmark, choose Standard 15M or 33M, Start. Or from a terminal:

    sculptforge --benchmark standard-15m
sculptforge --benchmark standard-33m
sculptforge --benchmark core-100m
  3. Read the result

    About a minute per size. A table shows the numbers; a JSON file and an MP4 of the run (with the numbers on screen) are saved. Send the JSON to be listed here.

Repeat the 805 million triangle run

The largest scene we list is core-800m: the same procedural head at micro level 5, 805,306,368 micro triangles, held in memory. It is in SculptForge 0.13.9 and later. One command:

Linux (in a terminal):

SF_HW_SIMULATE=floor sculptforge --benchmark core-800m --benchmark-no-video --benchmark-out result.json

macOS (in Terminal, with SculptForge in Applications):

SF_HW_SIMULATE=floor /Applications/SculptForge.app/Contents/MacOS/SculptForge --benchmark core-800m --benchmark-no-video --benchmark-out result.json

Windows (in PowerShell, from the unzipped portable folder):

$env:SF_HW_SIMULATE = "floor"; .\bin\sculptforge.exe --benchmark core-800m --benchmark-no-video --benchmark-out result.json

Leave the SF_HW_SIMULATE part off to run at your computer's own speed (floor holds the program to the entry-level budget, as in the rows below). The scene needs about 4.2 GB of memory and a 0.6 GB scene file, written once; with too little of either the program says so and exits. The first run writes the scene file; every run after that opens it (about a second here: 0.7 to 1.1 s). Send the JSON as below to be listed.

  • What we measured (three runs, the evening of 2026-11-21 US Mountain time, built from the 0.13.11 tag, commit b367bff9, the program's own JSON for each: run 1, run 2, run 3): orbit 211 to 213 frames a second (median 212); the slowest 1% of orbit frames 8.5 to 8.6 ms. Stroke timings are being re-measured. Three runs on one laptop: a range, not a promise.
  • The machine: an Apple M1 Pro laptop (10 cores, 30.9 GB, Linux), 1920 x 1080, vertical sync off, held to SculptForge's entry-level budget with SF_HW_SIMULATE=floor. It is a fast laptop slowed down in software, not a real entry-level computer: your numbers will differ, in either direction.
  • Memory: SculptForge held a peak of 1,640 to 1,658 MB (resident) plus 2,563 MB of graphics buffers; on integrated graphics those buffers are system memory, so about 4,200 MB in all. The program asks for about 8 GB free (6.4 GB and a margin: 7 GB is refused, 8 GB runs) before it starts, and stops with one line saying how much it needs and how much is free if you have less. A computer with a separate graphics card needs the 2,563 MB on the card.
  • Disk: the scene file is 0.6 GB (609 MB), written once to the program's cache folder. It needs about 0.9 GB free to write; with less it stops with a message and writes nothing.
The scene. A procedural head (skull, brow, nose, jaw, ears) built from a formula, so it's identical everywhere, with subdivision levels: about 15 or 33 million triangles. A scripted pen stroke (a figure eight, 240 pointer samples a second) goes through the same code a real pen does, with each brush in turn: Clay at 25, 60 and 120 px, Move (80 px), Smooth (60 px) and a 240 px Clay brush, then an orbit. Vertical sync off; the window size used is in each result.
The numbers. Frame p50 / p95 / p99: time per frame, the median and the slow ones you'd feel (16.7 ms is 60 fps). Stroke lag: not shown; Stroke timings are being re-measured. Worst stall: the longest the screen froze, including lifting the pen. Peak RAM: the most memory SculptForge held; GPU: its vertex and index buffers (on unified-memory machines like Apple silicon these share RAM). Lower is better everywhere.

Submit your result

The easy way: an issue

Open a Benchmark pack result issue, say who you are (a handle is fine, or leave it empty) and what the computer is, and paste results.json. A person checks it (the pack's hash, the numbers, no links in what you typed) and adds it here, usually within a day or two. Results of the standard scenes (--benchmark standard-15m) go in the older form.

What gets listed: the hardware text the program read, the SculptForge version and the timings, with the two lines you typed. No address, no account, no file paths.

The direct way: a pull request

From a clone of the repository:

python3 tools/benchmark/submit.py check result.json
python3 tools/benchmark/submit.py add result.json \
  --name "your handle" --machine "laptop model" \
  --video https://...

and open a pull request with the change to website/benchmarks/results.json.

SculptForge itself uploads nothing: the benchmark only writes files on your computer. The format: docs/benchmark.md.

Comparing with other apps

This page lists SculptForge results only. We don't run, publish or test against other sculpting applications' numbers or output. If you use another app, sculpt a similar mesh there and judge for yourself.
